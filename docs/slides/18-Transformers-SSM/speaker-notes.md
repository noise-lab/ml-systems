# Lecture 18 — Speaker Notes (Transformers and State-Space Models for Network Traffic)

Per-slide brief, one row per slide in deck order. In-deck notes (the `::: {.notes}` blocks) are also visible in reveal.js speaker view (press **S**). | 3 | What NetDiffusion Cannot Do | • **Figure:** the nPrint image of one flow, one packet per row, header bits as green (1), red (0), gray (absent) pixels; the only thing the diffusion model ever sees.<br>• Four structural limits, not tuning problems: the generator sees pixels, never a header field or a flag; one image is a fixed number of packets (about 1,024 rows), so a long flow is truncated; nothing in a pixel says ESTABLISHED, so compliance is patched afterwards by dependency-tree post-processing; one image is one flow, so there is no way to express a browser session with a dozen interleaved connections.<br>• Say which of these the rest of the deck addresses: an SSM answers the first three directly and makes the fourth (multi-flow) possible.<br>• NetDiffusion: Jiang et al., [arXiv:2310.08543](https://arxiv.org/abs/2310.08543) (SIGMETRICS 2024), covered in the previous lecture. |

| 6 | Embeddings: Words, Packets, and Flows | word2vec's idea (Mikolov et al., 2013): a word is a vector, similar meaning means nearby vectors, arithmetic captures analogies. Networking versions: nPrint bit vectors, ET-BERT byte tokens. Graphviz strip: words or packets → tokens → one embedding per token → attention over the sequence.<br><br>• Read first: [Lin et al., "ET-BERT" (WWW 2022)](https://arxiv.org/abs/2202.06335): BERT pre-training on unlabeled encrypted traffic, fine-tuned for classification.<br>• What to say: packets in a flow are tokens in a sentence; meaning comes from context in both, and nPrint is the deterministic, protocol-aware tokenizer ([nPrint](https://arxiv.org/abs/2008.02695)).<br>• IP2Vec (Ring et al., 2017) embeds addresses by the flow contexts they appear in; descriptive citation only. |
| 7 | The Transformer Architecture | Attention (query, key, value; weighted average of values with weights from query-key match) plus a feed-forward layer; multi-head attention learns several relations at once. Legacy figure is the encoder-decoder diagram from the paper.<br><br>• Read first: [Vaswani et al., "Attention Is All You Need" (NeurIPS 2017)](https://arxiv.org/abs/1706.03762).<br>• BERT is encoder-only (bidirectional context, classification); GPT is decoder-only (autoregressive generation).<br>• Networking example: the ciphersuite token's query attends to the protocol-version and certificate-chain tokens; that is exactly the relation a misconfiguration detector needs. Equation in the appendix. |
| 8 | The Scaling Problem: O(n²) Attention | Generated figure (`images/attention-vs-ssm-cost.svg`, log-log): n² for attention against n for an SSM scan, with 1,000, 10,000 and 100,000 packets marked. Numbers printed by `figures.py`: 10⁶, 10⁸, 10¹⁰ attention scores against 10³, 10⁴, 10⁵ state updates.<br><br>• A busy second is a thousand packets, a long TCP flow tens of thousands, a session millions; the gap between the curves is three to five orders of magnitude at those sizes.<br>• Second point: TCP is a state machine and a transformer only learns it implicitly from position patterns, which is brittle when transitions are far apart.<br>• Million-token context windows exist (flash attention lowers the constant, not the exponent), but the quadratic bill is paid on every sequence. |
| 9 | Attention Has No State | • **Figure:** top, the state view: one vector (ESTABLISHED, seq = x+1, ack = y+1) and one update gives the next packet; below, the attention view: the "next packet?" token draws a red score edge back to SYN, SYN-ACK, ACK, DATA, ACK and the thousands of tokens in between, every step.<br>• Problem one is representational: there is no slot in a transformer that holds "we are in ESTABLISHED"; the fact is implicit in the attention pattern over the handshake tokens and is recomputed at every position.<br>• Problem two is cost: the pairwise comparison that recomputes it grows with the square of the sequence, and a gigabit link produces on the order of a hundred thousand packets a second, so a token per packet (NetSSM uses a token per byte) fills any attention window in moments.<br>• Bridge: the next section says what a representation with state looks like, and the one after that gives the architecture whose core object is a state. |
| 10 | Protocols Are State Machines (section) | • Short detour into theory of computation because it names exactly what the image representation lacked and what the recurrent state of an SSM provides.<br>• Two slides: deterministic machines (TCP) and probabilistic ones (applications, Markov chains). |
| 11 | State Machines Generate Output | • **Figure:** the TCP client path CLOSED → SYN_SENT → ESTABLISHED → FIN_WAIT → CLOSED in Mealy notation, *input / output* on every arrow: connect() / send SYN; recv SYN-ACK / send ACK; app writes or recv DATA / send DATA, send ACK (self-loop); close() / send FIN; recv ACK and FIN / send ACK. TIME_WAIT and simultaneous close omitted; the full diagram is in RFC 9293, section 3.3.2.<br>• Definitions, precisely: a finite-state machine is (S, Σ, δ, s₀) with a finite state set S, input alphabet Σ, transition function δ: S × Σ → S, and start state s₀. A **Moore machine** adds an output alphabet Λ and an output function λ: S → Λ, so the output depends on the **current state only**. A **Mealy machine** has λ: S × Σ → Λ, so the output depends on the **state and the input** that triggered the transition. Any Mealy machine can be converted to a Moore machine (with more states) and vice versa.<br>• TCP reads naturally as Mealy: the packet it emits is a response to the event (connect, a received SYN-ACK, close), not a property of the state alone; the self-loop on ESTABLISHED is the clearest case, since one state emits DATA on one input and ACK on another.<br>• The point of the slide: students met state machines as acceptors (is this string in the language?); read the diagram instead as a device that produces the packets after the slash. A generative model of traffic is, at bottom, learning this machine. |
| 12 | Markov Models: Probabilistic State Machines | • **Figure:** a video-streaming client as a Markov chain: idle → fetch manifest → download segment (self-loop p = 0.85), with rebuffer (p = 0.05, returns with p = 1.0), paused (p = 0.07; resumes with p = 0.6 or goes idle with p = 0.4), and stop (p = 0.03). Probabilities are illustrative; the shape is the point.<br>• A Markov model is a state machine with a probability on every arrow instead of an input symbol: the next state depends only on the current state (the Markov property). TCP's transitions are deterministic given the input; an application's are not, because the user and the network inject randomness.<br>• Hidden Markov models, from the probabilistic-models lecture, are the same chain with the state unobserved and the packets as emissions; that is the classical way to learn a traffic generator from traces (estimate the states and the transition and emission probabilities).<br>• Bridge to the next section: a state-space model has a continuous hidden state and learned update rules, so it never writes down states or probabilities, but a well-trained one must have encoded both to emit valid traffic. That is what "learns the state machine implicitly" means.<br>• The open question on the slide is real: probe the hidden state of a trained NetSSM, cluster it, and check whether the clusters are SYN_SENT and ESTABLISHED. Nobody has published that; it is a good project. |
| 13 | State-Space Models (section) | • Transition: the previous section said traffic is produced by a state machine; this one introduces the architecture whose core object is a state. The framing is "what replaces attention?" |
| 14 | State Space Models: The Intuition | • **Figure:** the one-step state update (from the generative-models survey deck): h₍t−1₎ carried forward by A, packet xₜ written in by B, the new state hₜ read out through C as yₜ, with a dashed loop back for the next step.<br>• Core framing: a fixed-size state vector is a running summary; output comes from the state, not from the full history.<br>• Analogy to say aloud (moved off the slide): reading a book and keeping notes rather than memorising every word.<br>• The table is the takeaway: 10× longer sequence is 100× compute for attention and 10× for an SSM.<br>• Compare to RNNs: same recurrent shape, but SSMs are linear in the state, which is what lets them be trained in parallel (next slide). |
| 15 | The State-Space Recurrence | • **Figure:** the recurrence unrolled over time; blue row is the input bytes, orange row the states h₁…hₙ, green row the outputs, with A along the state chain, B on the way in, C on the way out.<br>• Read it aloud left to right: each state is the previous state transformed by A plus the new token projected by B; the output reads the state through C.<br>• The state never grows, which is the whole reason the cost is linear.<br>• The convolution view: unrolling the recurrence gives y as a convolution of x with a kernel built from A, B, C, so training runs as one parallel convolution. That is S4: Gu, Goel, Ré, "Efficiently Modeling Long Sequences with Structured State Spaces", [arXiv:2111.00396](https://arxiv.org/abs/2111.00396).<br>• If someone asks about discretisation: the continuous A, B become Ā, B̄ through a step size Δ, which becomes important on the Mamba slide. |
| 16 | Mamba: Selective State Spaces | • **Figure:** the selective-state sketch; the input token feeds a small selection network that produces Δ, B, C for that token, Δ discretises A and B, and the state update uses those token-specific matrices.<br>• The selective-copy intuition pump: given "a b [c] d e [f] g h" with brackets marking the tokens that matter, a fixed-rule SSM cannot copy only the marked ones; Mamba can because its gates depend on content.<br>• A large Δ means "attend to this token and reset", a tiny Δ means "ignore it"; that is the mechanism behind "learns when to store, skip, or retrieve".<br>• Mamba: Gu and Dao, "Mamba: Linear-Time Sequence Modeling with Selective State Spaces", [arXiv:2312.00752](https://arxiv.org/abs/2312.00752) (Dec 2023). Mamba-2, the NetSSM backbone: Dao and Gu, "Transformers are SSMs", ICML 2024, [arXiv:2405.21060](https://arxiv.org/abs/2405.21060).<br>• The reference implementation at [github.com/state-spaces/mamba](https://github.com/state-spaces/mamba) now also ships a Mamba-3; NetSSM's published results use Mamba-2, so do not over-claim about successors. |
| 17 | Why SSMs Fit Network Traffic | • The mapping is the argument of the deck: sequential, stateful, long, multi-flow traffic meets linear scaling, recurrent state, and selective memory.<br>• The recurrent hidden state is a learned protocol state machine: a TCP connection walks SYN_SENT → ESTABLISHED → FIN_WAIT and the state vector can track that progression; point back to the Mealy diagram.<br>• Contrast with diffusion, which relies on spatial image patterns (nPrint rows) to encode state implicitly, which is far less natural.<br>• The "~5× faster than transformers" cell is the Mamba paper's inference-throughput claim, not a NetSSM measurement; say so if pressed. |
| 18 | NetSSM: Design and Method (section) | • Now apply the theory to the concrete system: three stages, pre-processing, training, generation. |
| 19 | NetSSM Overview | • Three contributions to repeat later: reliable multi-flow session generation, 8× longer training context and 78× longer generation than transformer-based generators, and a semantic-similarity evaluation.<br>• "Multi-flow" means a session with several interleaved flows, not a longer single flow; prior work never addressed it, it was a gap rather than a failed attempt.<br>• Paper: [arXiv:2503.22663](https://arxiv.org/abs/2503.22663); code: [github.com/noise-lab/netssm](https://github.com/noise-lab/netssm). |
| 20 | The NetSSM Pipeline | • **Figures:** top, the three stages as a flow (real labelled PCAPs → tokenize → train Mamba-2 with next-token cross-entropy on 100 K-token contexts → seed with an application token → generate autoregressively → detokenize to a synthetic PCAP); bottom, the architecture figure from the paper.<br>• Walk left to right and stress that there is no post-processing stage for protocol compliance, unlike NetDiffusion's ControlNet plus dependency trees.<br>• Generation is seeded by a label token such as `<\|netflix\|>`, so the model is conditional on application class. |
| 21 | Tokenization and Training | • **Figure:** the first bytes of a packet in hex on top, and the token sequence the model sees below: an application label token, one ID per byte (0x45 → 69, and so on), a `<\|pkt\|>` boundary, then the next packet.<br>• Compare to NetDiffusion's nPrint encoding of packets as bit-level image rows: NetSSM's byte tokens are simpler and generalise across protocols without redesigning the representation.<br>• Training: next-token cross-entropy, no per-packet labels, batch size 1, sequences up to 100,000 tokens (about 943 packets), Mamba-2 backbone. The 100 K context versus roughly 12 K for transformer-class generators is the core scaling advantage.<br>• Hands-on pointer: the notebook `example/train_netssm_from_scratch.ipynb` in [github.com/noise-lab/netssm](https://github.com/noise-lab/netssm) trains a small model end to end on Colab; it needs a GPU runtime, so tell students to pick one before running. |
| 22 | Evaluation (section) | • The evaluation framework is itself a contribution; introduce the three dimensions before any result so students know why each metric exists. |
| 23 | A Three-Dimensional Evaluation Framework | • **Figure:** synthetic and held-out real PCAPs feed three evaluators: statistical similarity (JSD of packet-size distributions), downstream ML utility (train on synthetic, test on real), and semantic similarity (protocol rules and application behaviour), each with its own verdict.<br>• Ask why statistical similarity is not enough: a model can match every marginal byte distribution and still emit syntactically invalid TCP.<br>• Ask why ML utility is not enough: a classifier can score well for spurious reasons unrelated to protocol fidelity.<br>• Semantic similarity is the hardest to fake and the most practically meaningful. |
| 24 | Results: Statistical and ML Performance | • **Figure:** two bar charts drawn from the paper's numbers. Left, JSD: NetShare 0.16, NetDiffusion 0.04, NetSSM 0.02. Right, random-forest accuracy when trained entirely on synthetic data and tested on real: NetShare 0.13, NetDiffusion 0.16, NetSSM 0.97.<br>• The 0.97 is the money number: it answers the practitioner's question "can I train my classifier on this?"<br>• The 0.16 for NetDiffusion is the sharper lesson: packet-level fidelity in the marginals did not make the data useful for training real classifiers.<br>• The per-application breakdown is in `figures/evaluation_detailed.png` in this folder for a seminar-depth question. |
| 25 | Results: ML Utility vs. Synthetic Data Mix Rate | • **Figure:** accuracy as the synthetic share of training data goes from 0 to 100 %, for application-level and service-type classifiers.<br>• NetSSM stays near 0.97 all the way to 100 % synthetic; NetDiffusion and NetShare fall off steeply, so their synthetic data actively hurts.<br>• Implication to say out loud: an organisation with no access to real traffic could train a production-grade classifier on NetSSM output alone. |
| 26 | Results: Packet Size Distributions | • **Figure:** kernel density of average packet size, generated versus ground truth.<br>• Read the shape: the left peak is ACKs and small control packets, the right peak is MTU-sized data packets; a model that only gets the mean right would produce one mode and fail this test.<br>• `figures/ks_sizes.png` in this folder has the KS-statistic version if someone asks for a formal test. |
| 27 | Results: Semantic Similarity — TCP Compliance | • **Figure:** the TCP exchange as a chain, SYN → SYN-ACK → ACK → data and ACKs with advancing counters → FIN or the partial teardowns seen in the wild, with the hidden state shown tracking the connection's phase, counters, and options.<br>• Generated traces have correct handshakes, valid sequence and acknowledgment progression, and advanced options (timestamps, window scaling, SACK), and they pass standard TCP validators.<br>• The anomalies point matters: real captures contain partial teardowns and conflicting flags, and NetSSM reproduces those too, which is fidelity, not a bug.<br>• Contrast: NetDiffusion needed external correction to fix protocol violations; here compliance emerges from the recurrent state. Point back to the Mealy diagram: the model has learned the machine. |
| 28 | Results: Multi-Flow Sessions | • **Figure:** an illustrative timeline of one video-streaming session with four interleaved flows: CDN endpoint setup (TLS handshake, manifest), two segment-download bursts, and a small periodic control flow; marker size scales with packet size, ticks are ACKs. It shows the shape NetSSM reproduces, not a generated trace.<br>• Ask what breaks with single-flow synthetic data: IDS signatures that rely on cross-flow correlation, load balancers tested with unrealistic session patterns, streaming QoE models that need the setup-then-segments sequence.<br>• This is the gap that motivates NetSSM's headline claim. |
| 29 | Comparison and Context (section) | • Pull back from the results to where NetSSM sits among the generators, to the LLM-adaptation line of work, and to the caveat every synthetic-data project must face. |
| 30 | Comparison to Prior Work | • **Figure:** training context and longest generated trace on a log scale: NetDiffusion about 12 K and 1.3 K tokens, NetSSM 100 K and 100 K, the 8× and 78× from the abstract.<br>• Translate the 78×: NetDiffusion generates about 1,300 tokens, a dozen packets; NetSSM generates about 100,000 tokens, roughly 943 packets, an entire TCP session rather than a handshake.<br>• NetShare has no context or generation length in tokens because it generates flow statistics, not packets. |
| 31 | Architecture Summary and Tradeoffs | One table, five columns: GAN/NetShare (flow stats, no state, low fidelity), diffusion/NetDiffusion (image to pcap, ~1024 packets, repaired afterwards), transformer/ET-BERT (tokens, O(n²)), SSM/NetSSM (raw packets, O(n), state inside, less spatial fidelity).<br><br>• No universally best architecture: packet-level detail wants diffusion or SSM, long traces want SSM, contextual protocol analysis wants a transformer, flow statistics are enough for a GAN.<br>• Say "hybrid" once: the field is combining them. |
| 32 | NetLLM: Adapting LLMs to Networking Tasks | NetLLM (Wu et al., SIGCOMM 2024): fine-tune an existing LLM for viewport prediction in 360° video, adaptive bitrate selection, and cluster job scheduling; a multimodal encoder turns time series into LLM tokens; the LLM emits the decision; beats task-specific algorithms and generalizes to unseen environments.<br><br>• Read first: [arXiv 2402.02338](https://arxiv.org/abs/2402.02338).<br>• What to say: an existence proof that you need not train a networking foundation model from scratch; the surprising part is generalization across environments, which suggests the LLM's reasoning is doing work beyond memorizing the training environment.<br>• The engineering problem is the modality gap: network data is time series, not text. |
| 33 | Privacy Caveat: Synthetic ≠ Automatically Private | • The vignette: Tran, Liu, Li, Feamster, "Quantifying the Privacy Implications of High-Fidelity Synthetic Network Traffic", [arXiv:2511.20497](https://arxiv.org/abs/2511.20497), posted November 2025.<br>• What it shows: membership-inference attacks can tell whether a user's flows were in the training set, and the paper proposes network-specific privacy metrics for identifier memorisation, sensitive-property leakage, and topology extraction.<br>• Background to say aloud: membership inference is Shokri et al. (IEEE S&P 2017); differential privacy (Dwork and Roth, 2014) adds calibrated noise so no single example moves the output much, and strong guarantees (epsilon below 1) degrade traffic fidelity substantially.<br>• The trilemma to write on the board: similar enough to train real classifiers, diverse enough to add information, private enough not to leak individual flows.<br>• Cold call: before releasing NetSSM traces to a partner university, what would you do? (Differential-privacy training, a membership-inference audit, redaction of rare or unique patterns.)<br>• Check at the next refresh whether this preprint has a venue. |
| 34 | Limitations and Open Problems | • Limitations: TCP-focused (UDP and QUIC are future work), byte-level modelling of TLS-encrypted payloads is an open question, batch size 1 limits training throughput, no differential-privacy guarantee in the base model.<br>• Directions: QUIC and UDP, hybrid SSM-plus-diffusion architectures, networking foundation models (NetFound: [arXiv:2310.17025](https://arxiv.org/abs/2310.17025)), standard semantic-similarity benchmarks, the privacy-utility tradeoff.<br>• Context transfer (train on VPN Netflix, generate VPN YouTube?) is the networking version of zero-shot generation and a good project pitch.<br>• Flip the question: what would motivate a fourth architecture after SSMs? Hybrids and foundation models are the two live answers. |
| 35 | Summary (section) | • Close the arc: GANs (flow stats) → diffusion (short raw packets) → SSMs (long, multi-flow, protocol-compliant), each fixing the last gap and opening a new one. |
| 36 | Key Takeaways | • Three contributions: first reliable multi-flow generator; 0.97 downstream accuracy versus 0.16 for prior art and JSD 0.02 versus 0.04–0.16; the three-dimensional evaluation.<br>• Broader lesson: architecture choice matters for long, stateful sequences, and Mamba's linear scaling and selective state line up with how protocols behave.<br>• The state-machine bullet is the new thread of this deck: TCP is a deterministic (Mealy) machine, an application is a probabilistic one, and a generator has to learn both the states and the transitions; the SSM's recurrent state is where they live, and whether you can read them back out is open.<br>• Point students at the code and notebook: [github.com/noise-lab/netssm](https://github.com/noise-lab/netssm).<br>• Ask: which of the three evaluation dimensions matters most for your project's application? |

| 43 | State-Space Recurrence | h_t = A h_{t−1} + B x_t, y_t = C h_t: a discrete linear dynamical system; in Mamba A, B, C are functions of x_t. Source: [Gu and Dao, 2023](https://arxiv.org/abs/2312.00752). One update per packet, fixed-size state, linear cost. |
